## 🧠 Core Behavioral Logic (The ANDP Blueprint)

This section defines the "soul" of the window manager. All modifications must respect these logical flows to maintain UX consistency.

### 1. Advanced Snapping & Tiling
*   **Trigger Zones:** Screen is divided into 4 edge bands (Top, Bottom, Left, Right) and 4 corner quadrants.
*   **Sensitivity:** Dynamic threshold (default 15dp-100dp). Snap Preview appears when the cursor/finger enters these zones during a drag.
*   **Tiling Grid Engine:** Scans existing docked windows to identify "Gaps" (empty regions). Snapping to a gap ensures perfect non-overlapping placement.
*   **Un-Snap Gesture:** Pulling a window away from its snapped edge by >10dp automatically restores its previous freeform dimensions.

### 2. The "Honest Stack" Visibility
*   **Existence-Based Tracking:** Title bar frames are tied to the **Task ID**, not just visibility flags. If an ID is in the system's "Active Task" list, it is valid.
*   **Top-Task Absolute Immunity:** The absolute top window in the system stack is granted immunity from all hiding rules. It always shows a title bar, bypassing Android 12 visibility reporting bugs.
*   **Back-Button Kill Switch:** Pressing "Back" or swiping an app away deletes its Task ID. The service detects this loss and destroys the frame **instantly (0ms delay)**.
*   **Restoration Shield:** Unminimizing an app grants it a **3-second protection window** where the frame cannot be removed, allowing time for slow system wake-up animations.

### 3. Title Bar Styling & Branding
*   **Dynamic Palette Analysis:** App icons are analyzed on launch to find the "Dominant Color." The title bar background is set to this color for a native look.
*   **Internal Decoration:** activities like `TaskManager` and `ProcessInspector` are whitelisted as "Decorated Windows" and receive standard frames.
*   **Interaction State:** Title bars become **translucent (40% alpha)** during active drag/resize gestures to reveal the workspace context underneath.

### 4. Multi-Window Isolation
*   **Task-Level Identity:** Package-name rules are strictly forbidden for multi-window apps (e.g., Chrome). 
*   **Identity Purity:** Snapping "Chrome Window A" must never affect the style or state of "Chrome Window B." Every logic check must use the unique **Task ID**.

### 5. Pill Mode vs. Standard Mode
*   **Standard Mode:** Full-width title bar spanning the entire window top.
*   **Pill Mode (Snapped/Maximized):** Compact, floating pill centered at the top. 
*   **Pill Auto-Shrink:** Inactive pills (no hover/touch for 3s) shrink in scale and fade to 40% opacity. They "wake up" instantly on interaction.

### 6. Auto-Hiding & Trigger Logic
*   **Collapsed State:** Title bar slides off-screen via hardware-accelerated `translationY`, leaving only a thin (8dp-16dp) touch-sensitive strip.
*   **Expansion Trigger:** 
    *   **Mouse:** Moving pointer into the top strip triggers smooth slide-down.
    *   **Touch:** Tapping the thin strip expands the bar.
*   **Pass-Through:** Collapsed bars are marked `FLAG_NOT_TOUCHABLE` outside the strip to allow interaction with app-level tabs/buttons underneath.

### 7. Premium Notification "Living Object" Physics
*   **Hybrid Positioning Architecture:** 
    *   **Collapsed (True Vertical Center):** Icons and right-side slots must be mathematically centered relative to the card's total physical height. This must be dynamic to handle varying line counts (1-line vs 2-line summaries) without visual "squeezing."
    *   **Expanded (Fixed Top Baseline):** Elements must physically slide up to a fixed baseline (exactly 12dp from the top edge) to form a structured header row.
*   **Parallel Rail Animation:** All header elements (Icon, Text, Thumbnail, Chevron) must travel on identical vertical "rails" using a shared animated state (e.g., `verticalTravel` or `verticalBias`). This ensures they move as a single physical entity rather than individual pieces.
*   **Physical Card Growth:** Always use `animateContentSize` on the outer Card container. Internal content must use symmetrical vertical padding (12dp) to prevent image clipping and provide professional breathing room.
*   **Thumbnail Morphing:** Image thumbnails must smoothly interpolate dimensions (e.g., 36dp to 48dp) during the slide-to-top transition.

## 🛡️ Critical Guidelines & Pitfalls (Guardrails)

When making modifications, **you must strictly adhere** to the following Android platform compatibility and behavioral rules:

1. **ART Hidden API Restrictions (Android 14+):**
   * Do not use standard meta-reflection for non-SDK interfaces.
   * **Rule:** Initialize LSPosed `HiddenApiBypass.addHiddenApiExemptions("L")` in `FreeformOverlayService` to prevent runtime crashes.
2. **Programmatic Focus Routing:**
   * Do not inject simulated taps (`input tap x y`) to focus apps underneath overlays—Android 14's tapjacking/overlay filters will block them.
   * **Rule:** Route active input focus programmatically via `setFocusedRootTask` (falling back to `setFocusedTask` if absent) over Shizuku Binder IPC.
3. **High-Frequency Gesture IPC Throttling:**
   * Avoid calling WindowManager layout updates on every raw touch move event on high-refresh-rate screens (90Hz/120Hz).
   * **Rule:** Rate-limit coordinates to **at most 60Hz (16ms)** using the non-blocking throttled rate limiter.
4. **Touch Safety (InputDispatcher Safety):**
   * **Rule:** For finger inputs (`TOOL_TYPE_FINGER`), defer window re-indexing or task ordering calls (`moveTaskToFront`) until `ACTION_UP` or `ACTION_CANCEL` to prevent system-level `InputDispatcher` cancellations.
5. **Milestone Backup (GitHub Push):**
   * **Rule:** If changes impact **Core Architectural Modules** (e.g., Overlay Service, Gesture Engine, Shell Executor), the agent must ask for user permission to `commit` and `push` to GitHub before exiting the session.
   * **Purpose:** Ensures a "Cloud Save Point" exists for catastrophic recovery, keeping local history and remote history in sync for major logic shifts.
